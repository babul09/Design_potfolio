02 / HOW I WORK

Useful beats complicated.

My goal is not to add AI to everything. It is to find the friction, test whether a tool helps, and keep people in control.

01

Start with the friction

Understand the task and the person doing it before choosing a model or framework.

↘
02

Prototype the smallest useful thing

Build a focused workflow that can be tried, observed, and improved quickly.

↗
03

Measure, don't assume

Use repeatable test cases and honest evaluation instead of unsupported claims about time saved.

↘
04

Keep humans in the loop

Make AI outputs editable, traceable, and easy to reject when they are wrong.

↗

03 / PROJECT NOTES

What each prototype explores.

A little more detail on the problem, intended workflow, and what will be tested.

01 Motion DNA ＋

Question: Can a procedural animation system become easier to explore when parameters are exposed through a live interface?

Planned tests: Time to create and compare configurations, parameter-boundary handling, frame-rate stability, and reproducibility.

Next milestone: Add parameter controls and save/load presets to the existing Go simulation.

02 Sketch-to-Concept ＋

Question: Can a single workflow make visual concept iteration more organized and traceable?

Planned tests: Time to create a reviewable concept sheet, adherence to explicit brief constraints, and ease of retrieving previous versions.

Next milestone: Connect a brief form, sketch upload, prompt generation, and image-generation provider.

03 Critique-to-Checklist ＋

Question: Can AI reduce the manual work required to turn review notes into a reliable action list?

Planned tests: Extraction precision and recall, unsupported claims, manual correction rate, and time to approve the output.

Next milestone: Build a structured extraction endpoint with editable results and source traceability.
