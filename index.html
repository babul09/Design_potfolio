03 / PROJECT NOTES

What each prototype explores.

Implementation details, controls, evidence, and current limitations.

01 Motion DNA ＋

Motion DNA renders a real time 2D simulation in Go and Ebiten, delivered in the browser through WebAssembly. Its articulated motion uses connected points and distance constraints; configuration, chain logic, and rendering are separated across the codebase.

Controls: Choose fish, snake, or lizard rigs; adjust spine resolution, segment length, body mass, follow speed, flex, and flex rate; lead the rig with the pointer; pause; save presets; compare A/B setups; and export PNG frames or JSON settings.

What I learned: Small changes to segment length, follow speed, and flex noticeably affect movement. Browser deployment and input handling are part of the product, while separating configuration, simulation logic, and rendering makes the system easier to extend.

Evidence: Live demo · Repository. No quantitative performance or constraint error benchmark is reported.

02 Sketch-to-Concept ＋

Forma combines a written brief, optional reference sketch, editable prompt, generated visual directions, and a curated concept sheet in one workspace. It uses React with Vite for the frontend and a FastAPI backend.

Generation: Google Gemini image generation is available through the Interactions API and requires a configured GEMINI_API_KEY. If local fallback is selected, or Gemini is unavailable or errors, the app creates a labeled local SVG study. Each concept records its source.

Persistence and limits: Projects, briefs, prompts, references, concepts, and notes autosave in the current browser. There is no account sync or server side project storage. Image generation depends on provider availability and prompt quality; the local fallback is an SVG study, not an AI generated image.

Evaluation: A repeatable plan checks adherence to constraints, diversity, regeneration and correction frequency, and iteration clarity. Results have not yet been reported. Evidence: Repository.
